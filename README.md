# 卦方 Guafang

> **64 六爻指令 + 20 方位 = 85 条 · x86-64 原生 · 自举进行中**

---

## ⚠️ 暂不支持符号写法

**源码里不许出现 `+ - * / % & | ^ << >> = == != < > <= >= [ ] ,`**

这些全部换成编码：

| 想写 | 必须写 | 想写 | 必须写 |
|------|--------|------|--------|
| `+` | `ht` | `=` | `a0` |
| `-` | `hz` | `==` | `a1` |
| `*` | `hh` | `!=` | `a2` |
| `/` | `hl` | `<` | `a3` |
| `%` | `hf` | `>` | `a4` |
| `&` | `hs` | `<=` | `a5` |
| `|` | `hr` | `>=` | `a6` |
| `^` | `hd` | `[` | `a7` |
| `<<` | `dh` | `]` | `a8` |
| `>>` | `dl` | `,` | `a9` |

**写符号直接编译报错，不会静默通过。**

```
第 3 行：符号『+』不许用，卦方要用指令『ht』
第 4 行：符号『=』不许用，卦方要写『a0』
```

**理由**：符号在不同终端、输入法、编码下会出歧义；字母数字开头的编码永不冲突，词法一眼就能切。

---

卦方（`.gf`）是一门纯命令式编译语言。没有 C 语法包袱，没有运行时要背，编译器自己输出 x86-64 机器码或 GNU as 汇编，不经第三方汇编器也能直接落地。

编译器用 C 写成（`gfx.c`），当前正在把它自己用卦方重写一遍（`bootstrap.gf`），目标是 **自举**：让卦方编译自己。

---

## 标点：两组编码

卦方源码不用 ASCII 标点，全部换成两位数字/字母编码，避免中文输入法与符号歧义。

### 第一组 `00`–`09`

| 编码 | 含义 | 编码 | 含义 |
|------|------|------|------|
| `00` | `#` 注释 | `05` | `;` 分号 |
| `01` | `(` 左括号 | `06` | `@` 地址/引用 |
| `02` | `)` 右括号 | `07` | `^` 指针/异或 |
| `03` | `"` 字符串边界 | `08` | `{` 作用域开始 |
| `04` | `、` 顿号/分隔 | `09` | `}` 作用域结束 |

`03…03` 成对，内部直接写 `03` 即输出双引号，**没有转义机制**。

### 第二组 `a0`–`a9`

| 编码 | 含义 | 编码 | 含义 |
|------|------|------|------|
| `a0` | `=` 赋值 | `a5` | `<=` |
| `a1` | `==` | `a6` | `>=` |
| `a2` | `!=` | `a7` | `[` 下标左 |
| `a3` | `<` | `a8` | `]` 下标右 |
| `a4` | `>` | `a9` | `,` 参数分隔 |

字母开头，与数字常量绝不冲突。字符串内不还原，前面紧跟标识符字符时也不还原（防 `data0` 这类名字被误伤）。

## 指令集

八组，每组八个，共 64 条（六爻）；再加 20 个方位标记，合计 85。

| 组 | 前缀 | 卦名 | 职责 |
|----|------|------|------|
| 声明 | `t_` | 乾 | 函数 `tt` / 变量 `tz` / 常量 `th` / 结构体 `tl` / 数组 `tf` / 全局 `ts` / 枚举 `tr` / 布尔 `td` |
| 函数 | `z_` | 兑 | 调用 `zt` / 返回 `zz` / 标签 `zh` / 回调 `zl` / 取址 `zf` / 内联汇编 `zs` / 断言 `zr` / 系统调用 `zd` |
| 运算 | `h_` | 离 | 加 `ht` 减 `hz` 乘 `hh` 除 `hl` 取模 `hf` 位与 `hs` 位或 `hr` 位异或 `hd` |
| 控制 | `l_` | 震 | 跳转 `lt` 相等跳 `lz` 不等跳 `lh` 循环 `ll` 递增 `lf` 跳出 `ls` 条件 `lr` 开关 `ld` |
| 输入 | `f_` | 巽 | 键盘 `ft` 文件 `fz` 内存 `fh` 端口 `fl` 数组 `ff` 成员 `fs` 栈指针 `fr` 逻辑非 `fd` |
| 输出 | `s_` | 坎 | 屏幕 `st` 文件 `sz` 内存 `sh` 端口 `sl` 数组 `sf` 成员 `ss` 重置栈 `sr` 日志 `sd` |
| 内存 | `r_` | 艮 | 栈分配 `rt` 回收 `rz` 转型 `rh` 重分配 `rl` 清零 `rf` 释放 `rs` 申请 `rr` 拷贝 `rd` |
| 数据 | `d_` | 坤 | 整数 `dt` 空值 `dz` 左移 `dh` 右移 `dl` 数组字面量 `df` 结构体字面量 `ds` 取反 `dr` 字符串 `dd` |

20 个方位标记（`Zd Zn Zx Zb` / `Db Dn Dx Dz` / `Nd Nx Nb Nz` / `Xd Xn Xb Xz` / `Bd Bn Bx Bz`）见 [`卦方指令集.md`](卦方指令集.md)。

> 运算类**必须写指令**，不写符号：加法写 `ht`，减法写 `hz`，以此类推。

## 命名铁律：标识符不许出现中文

```
tt zhu 01 02 08          ← 对：名字全 ASCII
    tz n = 42
    puts 01 "值 = " 02   ← 对：中文只在 03 字符串里当数据
    zz n
09

tt 主 01 02 08           ← 错：函数名是中文，编译器直接报错
    tz 缓冲 = 1          ← 错：变量名是中文
09
```

**中文只许出现在三个地方**：

| 位置 | 允许中文 | 说明 |
|------|---------|------|
| `00` 注释 | ✅ | 注释不进后端，随便写 |
| `03…03` 字符串 | ✅ | 是数据，按 UTF-8 字节落地 |
| 文件名 | ✅ | `学/01入门/02-输出文字.gf` 没问题 |
| **命令 / 名字** | ❌ | `tt tz ts tf th tl tr td zt zz` 后面的标识符、变量名、函数名、字段名、内建名 |

`03…03` 字符串是**输出内容**：里面的中文按 UTF-8 原样落地，不转义、不改名，想打印什么就写什么。两个注意点——字符串里不能再出现 `03` 本身（它是收尾定界符，会提前闭合）；字符串里的 `00` 是内容，不是注释。

编译器在词法阶段就拦：名字里出现任何 `>= 0x80` 的字节，直接 `die`。`gfx`（stage0）与自举出来的 `gfx2` 都拦。

```
gfx: 第 3 行：名字『主』里有中文/非 ASCII 字符
        卦方铁律：命令和名字只能用 a-z A-Z 0-9 _
        中文只许写在 00 注释、03 字符串和文件名里
```

**为什么**：后端要把每个名字变成 `fn_xxx` / `g_xxx` 符号。中文走 `mangle` 会被展开成 `_e4_b8_bb`，名字一长就撞 900 字节上限；不走 `mangle` 的地方（函数地址取址）会把裸中文漏进汇编。自举时 `gfx2` 与 `gfx3` 就是差在这上面。

## 内建名（全 ASCII）

编译器内置的运行时调用，一律短英文名：

| 组 | 名字 |
|----|------|
| 输出 | `puts`(串) `puti`(数) `putc`(字节) `putw`(内存写) |
| 文件 | `slurp`(读) `wrfile`(写) `fsize`(长度) `rdfile`(载入) `rdbuf`(取缓冲) |
| 屏幕 | `scw` `sch` `fbad` `pitch` `mem` `ms` `key` `msx` `msy` `msb` `poll` `hr` `mi` `se` `sleep` |
| 绘图 | `px` `getpx` `fill` `frame` `text` `dnum` `dhex` `fillb` `sup` `srect` |
| 机器 | `in8` `in16` `out8` `out16` `in32` `out32` `ld8` `ld32` `st8` `st32` `halt` `icall` `cpuid` `ca` `cb` `cc` `cd` |

调用形式：`puts 01 "文字" 02`，即 `名字 01 参数… 02`。

## 一个最小程序

```
tt zhu 01 02 08
    tz a = 0
    a = 01 1 02 ht 01 2 02
    zz a
09
```

`tt zhu 01 02 08 … 09` 定义入口函数，`tz` 分配栈局部，`zz` 返回。`01 1 02 ht 01 2 02` 是 `(1) + (2)`。

## 构建

### Linux

```bash
cc -O2 -o gfx gfx.c            # enc.c 被 gfx.c 直接 include
./gfx 输入.gf -c -nx > 输出.s  # 出 GNU as 汇编
as --64 -o 输出.o 输出.s && ld -o 输出 输出.o 宿主64.o   # 链接宿主运行时
```

`宿主64.s` 是 Linux 宿主运行时（栈传参，8 字节一槽）。汇编后与编译产物一起链接。

### Windows

不需要 WSL，不需要 Linux 工具链：

```bash
pip install ziglang
zig cc -O2 -o gfx.exe gfx.c
gfx.exe 输入.gf -c -nx              # 文本汇编，stdout
gfx.exe 输入.gf -c -nx -obj -o x.obj # 可重定位对象
python run_win.py x.obj              # 纯 ctypes 装载执行，输出到 新清单999.txt
```

`run_win.py` 用 `VirtualAlloc` 把对象贴到低基址、回填重定位、挂上 Python 实现的内建，然后直接 `call`。

### 开关

| 开关 | ASCII 别名 | 作用 |
|------|-----------|------|
| `-c` | | 编译 |
| `-nx` | | 不出头尾样板 |
| `-bin` | | 直出机器码 |
| `-obj` | `-对象` | 可重定位对象 |
| `-lex` | `-词法` | 只吐词法流（给自举对拍） |
| `-sym` | `-符号` | 只吐符号表（给自举对拍） |

ASCII 别名是给 Windows/GBK 命令行用的，Linux 上中文原名照旧可用。

## 自举状态（如实）

**目标**：`gfx`（C 版）编译 `bootstrap.gf` → `gfx2`；`gfx2` 编译 `bootstrap.gf` → `gfx3`；最终 `gfx2 == gfx3`。

**当前：未达成。** `gfx2` 已经能跑起来并产出完整汇编，但与 C 版输出仍有差异，逐字节比对尚未通过。

已完成的自举块：求值、赋值、二元/括号表达式、参数与参数存回、`lr` 条件（含比较序列）、`ll` 循环（单条件与比较两种形态）、`zz` 返回、`zt` 调用（含参数内联表达式）、数组读/写（含表达式下标）、`fh` 内存读、`fr` 栈指针、`ls` 跳出、`Zn` 继续、`lh`/`lz` 比较跳转、位运算、全局标量/初值、函数名 mangle、`same`/`lookup` 名字匹配等。

未完成：标点还原的完整 pre-pass（`gfx2` 目前逐处识别两字节编码，遇深层嵌套会退化）、部分嵌套形态。

对拍工具现成：`-lex` / `-sym` 两路输出可与 C 版逐字节比较；`tests/` 下 40 个用例覆盖各指令块。

> 不虚报。`gfx2 == gfx3` 没到就写没到。
